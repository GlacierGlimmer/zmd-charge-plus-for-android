# Android v0.1.1 本地实机测试修复

本轮处理首次悬浮窗不出现、全屏横屏顶部距离过大／尺寸偏大，以及统一版本的反馈。当前安装版本和应用当前版本均为 `v0.1.1`，versionCode 为 `2`；沿用原测试包名 `com.glacierglimmer.endfieldchargeplus.debug` 及 Debug 证书，可覆盖安装保留配置。测试轮次 r5 只用于验证记录，不加入产品版本名称。以后只有用户明确要求时才修改版本，详见 [版本约定](VERSIONING.md)。

## 首次启动与授权返回

修正采样和配置加载先后顺序造成的首次显示竞态。`HudRenderSession` 在收到真实配置之前不构建数据、不改变已显示方案、不发送输出；首次实际渲染一定触发显示。常驻悬浮窗意外未附着时可以恢复，短暂显示模式结束后则不会被普通采样反复唤出。

Activity 在每次恢复前台后加载配置，启动已启用的 HUD；返回系统悬浮窗授权页面后无需切换显示模式。未获悬浮窗权限时仍遵守系统限制，可通过首页启动按钮打开授权页面。停止 HUD 同时保存总开关为关闭，避免返回应用又自行启动。后台／开机启动继续按已有系统权限与开机开关执行。

## 顶部距离与横屏尺寸

原实现用“忽略可见性”的状态栏 Insets 为全屏游戏预留空间。现在从完整显示度量获取边距尺寸，单独读取已附着窗口的系统栏可见性；只在状态栏／导航栏实际显示时预留相应空间。局部窗口的边距距离不参与定位，保留之前防抖布局的设计。物理刘海仍按旋转后的真实边距避让，隐藏状态栏不会保留竖屏顶部空白。

横屏尺寸额外限制为屏幕短边高度的 70% 宽度，竖屏仍为短边的 94% 上限；保留用户缩放较小的设置。横屏胶囊主动缩小，比例一致；系统栏临时出现／隐藏只改变必要的避让位置，不让胶囊忽大忽小。90 单位的动画绘图窗口仍保留，动画完整性及进度环比例保持一致。

以反馈截图的 1280×2772 手机尺寸为测试样本：默认缩放下竖屏胶囊宽约 1203 px，横屏宽不超过 896 px。全屏横屏状态栏隐藏、刘海在侧边时，窗口顶部为 16 px，稳态胶囊顶部（含动画内部余量）约 40 px；实际设备存在分辨率、密度、系统栏及用户偏移差异，仍须手机确认。

实际拖动才保存自由位置；普通点按不会误启用缓存坐标。所选锚点与主动自由拖动的规则保留。如果此前主动拖动过，显示页的“恢复所选锚点”可以回到顶部等已选锚点。

实现参考：[Android 系统栏可见性](https://developer.android.com/reference/android/view/WindowInsets#isVisible(int))、[Insets 忽略可见性的含义](https://developer.android.com/reference/android/view/WindowInsets#getInsetsIgnoringVisibility(int))、[完整最大窗口度量](https://developer.android.com/reference/android/view/WindowManager#getMaximumWindowMetrics())。
