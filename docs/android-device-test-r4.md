# Android 实机测试修复 r4

本轮对应更新检查、轮播动画、Android/Root 变量、整体逻辑审查，以及顶部悬浮窗旋转后跑到屏幕中间的反馈。版本 `0.1.0-debug-r4`，沿用测试包的包名、versionCode 和 Debug 证书，可覆盖 r3 安装并保留配置。保留 r2/r3 的小米接入移除、通知限频、UI 卡顿和首次权限状态修复。

源码仅在本地修改，未提交或推送；手机验收状态为 **已修复，待实机验证**。网站问题记录仍以随包的完整 78 条详细快照为依据，本轮没有改写线上状态。

## 本轮修复

| 反馈 | 修复后的行为 |
| --- | --- |
| 没有与 PC 一致的更新检查 | 每次应用进程启动检查一次，关于页支持手动检查；本 Android 仓库 latest Release 无有效标签或返回 404 时回退 latest Tag，去掉 v 和测试后缀后比较数值版本。新版本在应用内提示，有通知权限时发通知，下载打开稳定 Releases 页面。并发检查合并，同一新版本的自动提醒不重复轰炸。 |
| 自动轮播缺少动画方式 | 悬浮窗轮播可选择简洁／完整动画，切换时真正应用到本次渲染方案；关闭轮播恢复方案自己的动画。原生通知的系统外观无法自定义，不显示此控件。无关设置变更不再重置轮播计时。 |
| 变量库含桌面占位项目 | 固定目录精简为 91 项，每项有已注册采集器的真实读取／计算代码。移除 425 个目录项，包括桌面专属、未实现及重复别名；受支持的旧别名仍可在模板中解析。逐核使用率和自定义 JSON 字段只按真实快照键加入。显存、Wi-Fi SSID、Windows 磁盘／传感器等无实现项目不再列出。 |
| Root 后仍不能读取受限硬件 | 高级页新增自愿开启的 Root 采集，先验证 su 返回 UID 0，再通过持久只读通道访问限定的 /proc、CPU/GPU/thermal 节点。CPU 总／逐核占用、频率／最大频率／温度、GPU 占用／频率／温度／型号及内存明细均使用真实数据源。缺失节点和失败结果显示 `--`，CPU 温度不会用电池温度代替。Root 关闭立即取消待执行授权并断开通道，手机未提供的指标不会凭 Root 被伪造。 |
| 顶部竖屏转横屏后位于中央 | 所选锚点与自由拖动坐标分开。旧配置中的缓存坐标不会自动覆盖顶部锚点；只有本版实际拖动后才启用分方向位置。调整锚点／偏移后恢复锚点定位，也可点“恢复所选锚点”。窗口使用完整显示区域的 maximumWindowMetrics，保留短边尺寸限制和去重布局，旋转不会使用小悬浮窗口的尺寸。 |

## 审查中修正的其他问题

审查覆盖应用与 core 的生产 Kotlin 源码、设置和配置迁移、生命周期、采样及真实数据源、悬浮窗布局与动画、原生通知、网络、权限、更新和诊断。源码清单记录 131 个 Kotlin 文件的哈希；这份清单用于明确本次构建范围，不代表已经证明全部逻辑无缺陷。

- 应用处于前台时，所有页面都能消费采样；HUD 关闭时变量库仍更新。退出应用且无 HUD 时停采样并断开 Root。编辑内容预览不再夺走运行中 HUD 的活动方案。保留 r2 的主线程通知移出、采样反馈循环切断和滑块松手持久化。
- 采样结果按采集器替换，不再残留已经删除的 HTTP 字段；采集器失败会使旧值变成不可用，不继续显示旧成功值。其他采集器数据保留。
- 前台服务先建立运行状态再订阅配置，避免启动时用默认配置覆盖已保存选项。首页等待首次权限检测结束后才允许启动，服务实际启动失败会提示失败；返回授权设置后刷新运行中的原生通知。
- Android 16 以下不展示原生实时通知模式，导入原生模式旧配置时改用悬浮窗。没有厂商后端选择，也没有小米 SDK、元数据或生产类。
- “电源插拔时显示”已接入实际电源广播。未知电池状态／供电来源显示不可用，充放电均可利用真实电荷计数差值估算电流，重置异常值受限制。满充能量标为估算值，CPU 核心标为应用可用逻辑核心，存储标签匹配实际分区。
- 时间变量的自动语言跟随系统。关于页、分享和首页显示真实 BuildConfig 版本。GPU 频率拒绝非有限值。
- 自定义 HTTP 重定向换源时不携带用户授权头，保留必要的公共请求头；初始请求同样受 HTTPS／回环地址规则限制。现有响应大小上限、超时、退避、密钥加密及日志脱敏保持有效。
- Root 失败不会自动删除方案中的硬件变量或表达式；可重新检测并在授权后恢复读取。

## 自动验证与证据

本版 `:core:test` 72 项、`:app:testDebugUnitTest` 377 项全部通过，`:app:lintDebug` 和签名 APK 构建通过。实际计数、证书、版本、哈希及补丁以同批 manifest.json 和 `验证记录/Android-r4/verification.json` 为准。

针对新增逻辑的回归包括：数值版本／Release-Tag 回退／超时／启动及并发去重、两种轮播动画与关闭恢复、Root 只读路径及授权门控、真实 CPU/GPU 节点夹具、CPU 与电池热区区分、旧坐标迁移及 1,000 次锚点旋转、失败采样与删除字段、电池未知状态和跨源重定向头。继续运行 r2/r3 的权限、通知映射、限频、反馈循环、尺寸及密度回归。

`android-r4-reader-coverage.json` 逐项列出 91 个固定变量的采集器文件／行号和数据来源，未绑定项为 0；动态字段另列实际来源。`android-r4-catalog-audit.json` 保留删减目录；`android-r4-source-inventory.json` 保留本次生产源码清单。

未连接 ADB 手机；Root 硬件验证使用测试节点夹具，系统通知展示与手机旋转行为仍需实机确认。新增 Release 出现时的真实系统通知、su 授权弹窗、厂商节点差异、系统杀后台及长时间功耗也待手机验收。自动几何测试不等同于实际设备 UI 测试。

实现依据：[GitHub Release API](https://docs.github.com/en/rest/releases/releases?apiVersion=latest)、[Android 最大窗口度量](https://developer.android.com/reference/android/view/WindowManager#getMaximumWindowMetrics())、[Linux devfreq 节点](https://github.com/torvalds/linux/blob/master/Documentation/ABI/testing/sysfs-class-devfreq)、[Linux thermal 接口](https://cdn.kernel.org/doc/html/latest/driver-api/thermal/sysfs-api.html)。

## 手机复测

- [ ] 覆盖安装后完全退出再启动：首页状态不必经过“显示”页才正确；启动失败时提示对应权限／原因。
- [ ] 关于页手动检查更新：有网、离线、超时、无新版本；新 Release 发布后验证启动提醒、通知及 Releases 跳转。同一进程切换页面／旋转不重复自动检查。
- [ ] 悬浮窗自动轮播分别选择简洁／完整，确认动画发生变化；关闭轮播后恢复方案自己的动画。原生模式没有无效动画选项。
- [ ] 变量库无桌面占位；HUD 关闭时值仍更新。高级页开启 Root 并授权，记录可获取的 CPU/GPU/内存字段；拒绝、撤销、关闭及重试均不丢失方案。无节点显示 `--`。
- [ ] 顶部居中锚点／顶部偏移反复横竖屏切换至少 10 次，保持顶部、比例稳定且不抖动。旧 r3 缓存位置不使横屏落在中央。真实拖动后验证分方向位置，并测试“恢复所选锚点”。
- [ ] 授权返回后运行中的原生通知及时刷新；收起／展开数值完整。电源插拔能够按设置短暂显示悬浮窗。
- [ ] HUD 关闭、悬浮窗、原生通知三种状态下连续滑动设置、切页和编辑方案，观察卡顿／闪退；退出应用后继续验证 HUD、锁屏、网络切换和系统回收。
- [ ] 编辑／删除 HTTP 数据源后无旧字段残留，失败不会显示上次成功值；导入旧方案、语言切换和 DeepSeek 日历仍正常。

日历和 DeepSeek 规则保持上一批实现：覆盖 2024–2030，2027–2030 的年度调休仍须以后续官方公告更新，不能当作已公布安排。Windows、macOS、Linux 的八个安装文件未重建。
