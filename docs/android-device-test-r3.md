# Android 实机测试修复 r3

此版对应 2026-10-09 的第二轮手机反馈。版本为 `0.1.0-debug-r3`，包名、versionCode 和 Debug 签名沿用原测试包，可直接覆盖安装。改动保留在本地，等待手机验收后再统一同步仓库。

## 首次启动的原生灵动岛状态

首页在配置加载、通知渠道建立和原生能力检测完成前显示“正在检测”，避免将旧缓存误报为未授权／不支持。首页和显示页共用检测结果；返回系统设置后重新读取实际权限，不需要先进入显示页。

权限页面只为确实有系统设置入口的功能保留操作按钮。原生实时通知入口打开系统的通知提升设置，前台服务／开机广播等安装时声明的状态不再提供无效的“去授权”按钮。运行状态按所选输出方式显示。

## 只保留生效的设置

移除灵动岛后端选择。旧配置中的 Auto、None、小米后端选择载入后统一迁移为 AndroidSystem，HUD 总开关继续保留用户选择。

| 控件 | 悬浮窗 | Android 原生灵动岛 |
| --- | --- | --- |
| 方案、文本、变量、系统／网络数据、轮播间隔 | 保留 | 保留 |
| 进度变量及上下限 | 进度环 | 系统进度条 |
| 位置、缩放、透明度、穿透、刘海避让、一直显示、动画 | 保留 | 隐藏 |

| 实时预览 | 实际悬浮 HUD | 收起短文字、展开文本、系统进度内容 |

原生灵动岛的位置、形状、配色与是否展示由系统决定，预览不模拟手机厂商的最终布局。继续保留 r2 的通知限频和卡顿修复。

## 横竖屏切换

使用显示器对应的窗口 Context 创建悬浮 View 和 WindowManager，窗口与绘图共用密度。旋转时同步更新密度；尺寸和位置从同一次屏幕度量计算，方向以实际屏幕宽高判断。

安全区域取自完整窗口度量，不再把随悬浮窗位置变化的 View 局部 Insets 用来重新定位悬浮窗。布局请求合并到主线程；参数未变化时跳过 updateViewLayout，避免相互触发布局造成抖动。横屏沿用短边尺寸约束，防止旋转后突然放大；横竖屏拖动位置分别保存。旋转中的旧拖动操作取消，避免写入错误方向的位置。

实现参考 [Android WindowManager 窗口度量](https://developer.android.com/reference/android/view/WindowManager#getCurrentWindowMetrics()) 和 [窗口 Context](https://developer.android.com/reference/android/content/Context#createWindowContext(int,%20android.os.Bundle))。
